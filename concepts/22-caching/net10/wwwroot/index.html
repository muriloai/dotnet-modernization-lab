Simulador de Concorrência e Stampede

Output Caching com Invalidação por Tags

Diferente do [OutputCache] do .NET Framework que exigia adivinhar a URL completa para limpar itens, o middleware de Output Caching do .NET 10 permite rotular respostas com tags de domínio e invalidar grupos inteiros com IOutputCacheStore.EvictByTagAsync.

Como testar:

  1. Clique em Consultar Categoria: observe o carimbo de data e hora gerado.
  2. Clique novamente: note que o carimbo de hora permanece idêntico, pois a resposta foi servida instantaneamente do cache sem passar pelo controller.
  3. Clique em Invalidar Tag: a tag específica será purgada. Na próxima consulta, um novo carimbo será gerado, enquanto outras categorias continuam intactas no cache!

Abstração IDistributedCache

No .NET 10, IDistributedCache padroniza a interface de cache distribuído. O código de negócio manipula bytes ou serialização JSON sem saber se o provedor subjacente é Redis, SQL Server ou uma memória compartilhada para testes.

Quadro Comparativo: .NET Framework 4.8.1 vs .NET 10

Característica .NET Framework 4.8.1 (Legado) .NET 10 (Moderno)
In-Memory Cache System.Web.Caching.Cache (estático, acoplado ao IIS) ou MemoryCache estático IMemoryCache via Injeção de Dependências com escopos claros e testáveis
Cache Stampede Sem proteção nativa: múltiplas threads atingem o banco ao expirar a chave Mitigado com GetOrCreateAsync e SemaphoreSlim por chave
Cache Distribuído Inexistente na BCL: cada fornecedor impunha sua própria API proprietária IDistributedCache padronizado (Redis, SQL Server, Memória)
Invalidação de Resposta [OutputCache] com remoção estrita por URL completa via RemoveOutputCacheItem Middleware OutputCache com EvictByTagAsync para invalidação semântica por tags
Prevenção de Locks de I/O Bloqueios síncronos com lock/Monitor, propensos a contenção de threads Semáforos assíncronos não bloqueantes (WaitAsync)
