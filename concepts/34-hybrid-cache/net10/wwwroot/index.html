Invalidacao por Tags (Eviction Seletiva)

No .NET Framework, invalidar todos os itens de uma categoria exigia varrer chaves manualmente no MemoryCache. No .NET 10, basta chamar RemoveByTagAsync("category:x")!

Diferencas Tecnicas: .NET Framework 4.8.1 vs .NET 10
Caracteristica .NET Framework 4.8.1 (Legado) .NET 10 (Moderno)
Arquitetura de Cache Isolada (System.Runtime.Caching.MemoryCache ou HttpContext.Cache). Sem integracao nativa com cache distribuido. Hibrida nativa (L1 in-memory + L2 distribuido como Redis ou Garnet) sob a mesma abstracao.
Cache Stampede (Thundering Herd) Nao protegido por padrao. Exige locks manuais (ReaderWriterLockSlim ou SemaphoreSlim), propensos a deadlocks. Protegido nativamente por lock por chave (keyed lock). Apenas uma factory e executada para concorrencias.
Invalidacao em Lote Inexistente. Desenvolvedores precisavam iterar dicionarios de chaves ou guardar colecoes em memoria. Nativa via Tags (RemoveByTagAsync). Invalida centenas de entradas correlatas em uma unica operacao.
Serializacao BinaryFormatter (obsoleto e inseguro) ou Newtonsoft.Json manual com alto consumo de memoria. Otimizada via System.Text.Json ou serializadores binarios configuraveis direto na camada L2.
Alocacao e Performance Alocacoes repetidas de delegados e objetos intermediarios de cache. Zero alocacao para Cache Hits na camada L1 e reaproveitamento de buffers via ArrayPool.
